# 代码交付门禁索引

本目录维护代码交付前的检视规范。
根 `AGENTS.md` 只保留门禁入口；具体范围、工具和失败处理写在本目录。

## 判定表

| 场景 | 需要检视 | 规范 |
| --- | --- | --- |
| C/C++ 业务代码、BUILD、接口/IPC 或跨模块逻辑 | 稳定性（询问制） | `stability.md` |
| IPC、不可信输入、权限或安全边界 | 稳定性（询问制）；安全规范待补 | `stability.md` |
| 纯测试、文档、注释、知识路由、格式调整 | 通常不适用 | 最终回复说明不适用原因 |

## 使用规则

- 默认按本次任务影响面选择检视项，不默认全仓扫描。
- 稳定性检视为询问制：业务代码改动时 Agent 先询问用户是否执行，用户确认后再按 `stability.md` 检视；
  仅涉及测试、文档、注释等非业务代码时无需询问，直接判定不适用。
- 若多个门禁同时适用，按相关规范分别说明结果。
- 门禁结果在最终回复中标注为：已执行、未执行、失败、不可用或不适用。
- 若 Agent 负责 commit 或 push，相关门禁失败或不可用时不继续 push，等待人工确认。
- 检视结论提取后，清理本次生成的报告和临时安装内容；保留持久工具和既有文件。
- 新增其他检视规范时，在本目录新增对应 `.md` 并更新判定表。
